# ADR-001: Формат ошибок RFC 7807

## Статус
Принято

## Контекст
Текущее API возвращает тексты ошибок или дефолтные ошибки FastAPI/Starlette. Требуется единый машинно-читаемый формат ошибок с полями `type`, `title`, `status`, `detail` и `correlation_id` для трассировки и автоматической обработки.

## Решение
Все HTTP-ошибки приводятся к формату RFC 7807:
- Вводятся глобальные обработчики/middleware, которые возвращают Problem Details JSON.
- Всегда включаем `correlation_id` (UUID4) в ответ и в логи.
- Валидационные ошибки (400/422), not-found (404) и внутр. ошибки (500) возвращаются в Problem Details без внутренних стек-трейсов и секретов.
- Тесты проверяют структуру Problem Details.

## Последствия
- Плюсы:
  - Единый, предсказуемый формат ошибок; удобен для тестов и мониторинга.
  - Снижает риск утечки PII в ошибках (NFR-07).
  - Улучшает трассировку между логами и запросами.
- Минусы:
  - Клиентам нужно парсить Problem Details.
  - Требуется привести все внутренние пути ошибок к единому виду.

## Связи
- NFR: NFR-04, NFR-07, NFR-05
- STRIDE: связанные элементы F5 (логирование)
- Тест: `tests/test_secure_coding.py::test_rfc7807_error`
