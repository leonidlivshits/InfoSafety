# ADR-003: Простейший rate limiting в приложении (gateway + fallback)

## Статус
Принято

## Контекст
NFR-08 требует защиты от пиков и злоупотреблений.
## Решение
- Ввести in-process fixed-window rate limiter как middleware:
  - По умолчанию 100 запросов в минуту на IP.
- При превышении возвращать Problem Details (RFC 7807) со статусом 429 и заголовком `Retry-After`.
- Добавить тесты, имитирующие всплески и проверяющие 429 ответы.

## Последствия
- Плюсы:
  - Соответствует NFR-08 и смягчает STRIDE DoS.
- Минусы:
  - In-memory реализация не работает в мульти-процессной/мульти-репликовой среде; нужно заменить на Redis
  для продакшена.

## Связи
- NFR: NFR-08, NFR-01
- STRIDE: F1 (DoS)
- Тест: `tests/test_secure_coding.py::test_rate_limit_block`
